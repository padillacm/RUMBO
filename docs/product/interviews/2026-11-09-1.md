# Interview 1 (2026-11-09)

Profile: the author of RUMBO; Python projects of their own; develops on Windows, tests in Linux
containers, deploys to Linux VMs. Counts as direct evidence with that caveat: not an external user.

## Answers (summarised, in the interviewee's terms)

1. **Last thing undone.** Frequent: the agent drifts from the guidelines without noticing. Found
   by testing the feature by hand, or because a test broke during development.
2. **How do you know nothing broke.** Only by using the feature, reading the logs and the code
   behind it. Slow when the code was generated by the agent without close supervision.
3. **Tests, CI or lint touched to pass.** Yes, routinely: implementing or changing a feature
   leaves tests broken and the agent edits them; when it cannot fix a lint finding it makes the
   configuration permissive. The changes were reviewed and accepted so as not to stay blocked.
4. **Written rules.** Specs per feature. Once a problem repeats, the agent starts adding junk or
   duplicated code and drifts from the spec.
5. **Tools tried and dropped.** OpenSpec and other spec-driven tools: too much time reviewing and
   correcting specs and navigating the changes.
6. **One action to block mechanically.** Already done through hooks: reading the project's
   credentials or specific files, and deleting things without the human's permission.
7. **Time before giving up.** One full sprint, then an assessment of what it contributed.
8. **OS and agent.** Windows for own projects; everything verified in Linux or a container;
   Linux VMs for deployment. Agent: Claude Code.

## What it confirms or changes

- Confirms the core pain of the brief (answers 1, 3): the agent weakens tests and relaxes lint
  under pressure, and the human accepts it to keep moving. That is the cheating genie, and the
  acceptance is the cognitive-debt consequence.
- Confirms the risk named in the PRD (answers 4, 5): spec-driven tools cost more in review than
  they return for small changes; the fix lane and the rigor levels exist for this.
- Confirms the lever (answer 6): hooks that block credential reads and deletions are the thing
  the interviewee already built by hand; RUMBO generalises it.
- Changes a number: the trial window is one sprint (two weeks), not the four weeks the brief's
  retention metric uses. Pilots should report at two and at four weeks.
- Confirms the platform mix (answer 8): native Windows for development plus Linux for
  verification is exactly the case slices 1 and 4 made work.
