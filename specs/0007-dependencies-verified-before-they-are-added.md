# F-0007: Dependencies verified before they are added (`rumbo verify-dep`)
Story: As a developer working with a coding agent I want every package name checked before it is
added (does it exist, how old is it, does it imitate a popular name, does it have known
vulnerabilities, is it on the index my project installs from) so that a hallucinated or
typosquatted name is caught before `uv add`, and the decision to add it stays with me.

Scope: the `verify-dep` subcommand of the CLI: `cmd_verify_dep` and the block under
`# verify-dep` in `src/rumbo/cli.py` (`POPULAR_PACKAGES` to `cmd_verify_dep`, without the
`cmd_check` that sits inside it) and its `argparse` entry. The command reports and exits; it adds
nothing and blocks nothing.
Decisions: ADR-0001 (standard library only), ADR-0014 (private index), ADR-0028 (every answer is
untrusted, credentials go only to the index). Written retroactively: it describes the code as it
is on 2026-11-21, and the last section lists what that code does not handle.

## Requirements (EARS)
<!-- Ubiquitous: The system shall… · Event: When…, the system shall… · State: While…, the system shall…
     Unwanted: If…, then the system shall… · Optional: Where…, the system shall… -->
- R1 (unwanted): If PyPI answers 404 for a requested name and no index is set (R5), then `verify-dep` shall print `<name>: does NOT exist on PyPI. Hallucinated name? (slopsquatting)`, make no further request about that name and give it the verdict 1.
- R2 (event): When PyPI knows the requested name, `verify-dep` shall print the package's canonical name, the version and summary PyPI reports, the day of its earliest file upload with its age in days, its repository URL and its number of releases, and shall warn `younger than 90 days: review with care` when that age is under 90 days, `declares no repository` when none is declared, and `the canonical name is '<name>'` when it differs from the requested one after PEP 503 normalisation; every string a server sent (PyPI here, the index in R6, the reason of an error in R8) shall be printed with each run of control characters, bidi marks and line separators replaced by one space and cut to 200 characters (a version to 60, the answering host of R6 to 80).
- R3 (unwanted): If the PEP 503-normalised name is within Levenshtein distance 2 of a name in `POPULAR_PACKAGES` and is not that name, then `verify-dep` shall warn `looks like a popular package: <names> (typosquatting?)`; the name compared is the canonical name of a package PyPI knows, or the requested name when an index is set and PyPI does not know it.
- R4 (event): When PyPI knows the requested name, `verify-dep` shall ask OSV (`POST https://api.osv.dev/v1/query`, ecosystem `PyPI`) about the canonical name and, when it returns any, warn `<N> known vulnerabilities in OSV (check the affected versions)`; if that request fails in one of the ways of R8, or the answer is not JSON, or not a JSON object whose `vulns`, when present, is a list, it shall print `(OSV not reachable: vulnerability check skipped)` and leave the verdict unchanged.
- R5 (optional): Where `--index URL` is given and not empty, or else where one of `UV_INDEX_URL`, `UV_DEFAULT_INDEX`, `PIP_INDEX_URL` is set and not empty (the first in that order), `verify-dep` shall take that value as the private index ("an index is set"), unless it is an `http(s)` URL whose host is `pypi.org` or `www.pypi.org`, in which case it shall behave as if none were set.
- R6 (state): While an index is set, `verify-dep` shall first request `<index>/<normalised-name>/` asking for PEP 691 JSON and accepting PEP 503 HTML, print `index: <url>` and then, `<host>` being the `host[:port]` of the index: on a 404, `exists on <host>: no. Hallucinated name? (slopsquatting)` (verdict 1); on a 200 answer that is not a package page, `could not query <host> (the index answered, but not with a package page). Verify by hand.` (verdict 2); on a page without a version, `exists on <host>: yes, no files` (verdict 1); otherwise `exists on <host>: yes` and `versions on <host>: N (latest X)`. A package page (`simple_page`, ADR-0028) is PEP 691 JSON with a `versions` list or a `files` list, or HTML with at least one anchor that names a distribution file with a PEP 440 version, the file name being the text of the anchor, or the last segment of its href only when the text is that name cut short and ended in `..>`; a charset Python does not know shall be read as UTF-8. X shall be the highest version in PEP 440 order among those not yanked, a version being yanked when every one of its files is (among all, with `, every file yanked` added, when all are), with `, a pre-release` added when it is a pre-release or a development release. When another scheme, host or port answered after a redirect, the `exists` line shall end with `(answered by <host[:port]> after a redirect)`, with `; the credentials were not sent there` inside the parentheses when the index URL holds credentials. It shall then run the PyPI checks of R2 to R4 with `(measured against PyPI, not against your index)` at the end of every line that reports one of them, and report a name PyPI does not know as `not on PyPI`, which is not a failure.
- R7 (ubiquitous): `verify-dep` shall never write the user name or the password of an index URL to stdout or stderr: the index is printed as `scheme://host[:port]/path`, with `***@` in place of the part of a path segment that ends in `@`, an error message is printed with the raw URL replaced by that form and the password by `***`, and a value that is not an `http(s)://host` URL is not echoed at all (R8). The credentials shall be sent only as a Basic `Authorization` header to the scheme, host and port of the index: a redirect inside them keeps the header, a redirect to another scheme, host or port is followed without it, and it is not attached again on a later hop. Over plain `http` they shall be sent only to an index on this machine (`localhost` or a loopback address); for any other, no request goes to the index and R8 applies with the reason `refusing to send the index credentials over plain http; use https`. An index on this machine shall be reached without the proxies of the environment, and the credentials of a proxy shall not follow a redirect to a target that is reached without that proxy.
- R8 (unwanted): If the index or PyPI cannot be read (a connection error, a timeout, an HTTP status other than 404, a protocol error, a redirect R9 refuses, a body that ends before its `Content-Length`, is larger than 32 MiB or is not complete 60 seconds after the request began, a PyPI body that is not JSON or is JSON nested too deeply), then `verify-dep` shall print `could not query <source> (<reason>). Verify by hand.` (the source: `PyPI`, or the `<host>` of R6), or `<name>: PyPI answered in an unexpected shape. Verify by hand.` when PyPI answers JSON of an unexpected shape (a list, an `info` that is not an object, an upload date that is not ISO), give the package the verdict 2 and go on, without a traceback, with the PyPI checks of that package when it is the index that failed and with the next package in every case. If the index value cannot be parsed as a URL, or is not `http(s)://host`, then it shall send nothing to the index, print for every package `could not query the index (<text>). Verify by hand.`, the text being `the index URL cannot be parsed (check the host and the port)` or `the index URL must be http(s): it has to start with http:// or https:// (value not shown: it may hold credentials)`, give them the verdict 2 and run the PyPI checks labelled as in R6. Every socket operation shall carry a 15-second timeout, Ctrl+C shall not be held until the 60 seconds pass, and a PyPI document with missing fields shall be printed with `?` and `(not declared)` in their place.
- R9 (ubiquitous): The only project data `verify-dep` shall put in a request is the package name. It shall accept as an argument a PEP 508 name, alone or followed by extras, a version specifier and a marker, which it shall set aside with `note: only the name '<name>' is verified, not its extras, version or marker`; if an argument is anything else (a URL, a path, a VCS reference, `name @ url`), then no request shall be made for it, it shall not be echoed, and `Error: argument <position> of verify-dep is not a package name (expected a name such as 'requests', with or without extras and a version; a URL, a path or a VCS reference cannot be verified). Nothing was requested for it.` shall go to stderr, the other arguments being verified all the same. The requests are `GET https://pypi.org/pypi/<name>/json`, `POST https://api.osv.dev/v1/query` with `{"package": {"name": <canonical name>, "ecosystem": "PyPI"}}` and, where an index is set, `GET <index>/<normalised-name>/` with the credentials of R7, the name percent-encoded into one path segment of both URLs. The PyPI and OSV requests shall be refused unless their URL is `https`, and no redirect shall be followed from `https` to plain `http`, to a scheme that is not `http(s)`, or to a URL whose authority is not plainly `host[:port]`. Every request shall go through `_fetch`, `_open` and an opener built by `_opener` (handlers for `http` and `https` only); no code of the CLI shall call `urlopen`, `build_opener` or `install_opener`.
- R10 (ubiquitous): `verify-dep` shall examine every argument of the command line and exit with the worst verdict among them (0 when nothing was flagged, 1 when a package does not exist or carries a warning, 2 when a source could not be queried or an argument is not a package name), and whatever the verdict its last line on stdout shall be `Reminder: the human approves every new dependency; justify it in the PR.`

## Data contracts and ownership
<!-- What two sessions (or two agents) must agree on BEFORE writing code. Omitting explicit data
     structures is what breaks parallel work (docs/method.md, section 3.1). -->
- Types / schemas: the command line `rumbo verify-dep NAME... [--index URL]`. From the PyPI JSON document: `info.name`, `info.version`, `info.summary`, `info.project_urls` (the first key matching `source|repo|code|github|home`, any case), `info.home_page` as the fallback repository, `releases: {version: [{upload_time_iso_8601}]}`. From OSV: `vulns: list`, counted. From the index: `SimplePage(versions: list[str], yanked: frozenset[str], answered_by: str | None = None)`, a `NamedTuple`; the versions are the strings of PEP 691 `versions` when it lists any, else those of the file names (`files[].filename`, or the anchors of a PEP 503 page); `yanked` holds the versions whose every file is yanked (`files[].yanked`, `data-yanked`); `answered_by` is the `host[:port]` that served the page when it is not the index. A version is read from a wheel name (second `-` field) or an sdist name (after the last `-`, suffix `.tar.gz`, `.tar.bz2`, `.tar.xz`, `.tgz` or `.zip`). `POPULAR_PACKAGES: tuple[str, ...]`, 56 normalised names fixed in the code. `INDEX_ENV_VARS = ("UV_INDEX_URL", "UV_DEFAULT_INDEX", "PIP_INDEX_URL")`. `HTTP_TIMEOUT = 15` (seconds, one socket operation), `HTTP_DEADLINE = 60.0` (seconds, one whole request), `MAX_BODY = 32 * 1024 * 1024` (bytes of one answer), `SHOWN_MAX = 200` (characters).
- Signatures: `cmd_verify_dep(args) -> int`; `resolve_index(flag: str | None, env: Mapping[str, str]) -> str | None` (`ValueError` with one of the two fixed texts of R8); `sanitize_index(url: str) -> str`; `simple_page(body: str, content_type: str) -> SimplePage | None` (None when the answer is not a package page); `parse_simple(body: str, content_type: str) -> list[str]` (its versions, `[]` when there is none or no page); `index_page(index: str, name: str) -> SimplePage | None` (None on a 404; `ValueError` when the scheme is not http(s), for credentials over plain `http` and for a 200 answer that is not a page); `index_versions(index: str, name: str) -> list[str] | None`; `latest_version(versions: list[str], yanked: Collection[str] = ()) -> str | None`; `pypi_info(name: str) -> dict[str, Any] | None` (None on a 404); `osv_vulnerabilities(name: str) -> int | None` (None when OSV is out of reach); `_lookalikes(name: str) -> list[str]`; `_show(value: object, limit: int = SHOWN_MAX) -> str`; `_http_json(url: str, payload: dict[str, Any] | None = None) -> dict[str, Any] | None`; `_fetch(request, direct: bool = False) -> _Answer` (`content_type`, `charset`, `body: bytes`, `url` of the last request); `_open(request, timeout: float, direct: bool = False)`; `_opener(direct: bool) -> OpenerDirector` (`direct`: without the proxies of the environment); `_Redirects.redirect_request`, the redirect rule of R7 and R9. `NETWORK_ERRORS` is the tuple of exceptions that become "could not query".
- Shared invariants: exit codes 0 nothing flagged, 1 flagged, 2 could not query or not a package name, the highest wins; everything is printed on stdout, except the `Error:` line of R9; the sanitised form is the only form of an index URL that is printed; with an index, the index answers existence and versions and PyPI answers the rest, each line saying which (ADR-0014); the index lookup failing does not skip the PyPI checks, and PyPI failing skips the OSV query; `_open` is the only place a connection is opened, called only by `_fetch`, itself called only by `_http_json` and `index_page`, and it is what the tests replace; `urlopen` is called by nothing; standard library only (`urllib`, `html.parser`, `threading`, ADR-0001).
- Files owned by this spec (one writer): the `verify-dep` block and `argparse` entry of `src/rumbo/cli.py`, `tests/test_verify_dep.py`, the tests of `tests/test_cli.py` listed above with the `index` fixture they use.
- Interfaces touched that other specs depend on: the command name, which the generated permissions allow the agent to run (`Bash(rumbo verify-dep *)` in `src/rumbo/templates/dot_claude/settings.json`, F-0004) and which RUMBO.md, the generated `AGENTS.md`, the pull request template, the `rumbo-ancla`, `rumbo-o` and `rumbo-review` commands and the manual G4 item "New dependencies verified" quote (F-0005). The guard (`src/rumbo/sensors/guard.py`) refuses, in an agent's shell, a `verify-dep` command with an option that begins with `--i`, or with one of the three index variables assigned before it (`tests/test_guard.py::test_bypass_spellings_are_blocked`): only the human chooses another index. No code reads the output or the exit code of `verify-dep`.

## NFR
At most 3 requests per package (index, PyPI, OSV), one after another, redirects not counted; each
has 15 s per socket operation, 60 s in total with its redirects, and an answer of at most 32 MiB
(R8). The 60 s and the 32 MiB were chosen without a measurement against PyPI (ADR-0028), and the
time to parse an answer is not under the deadline · 0 dependencies · 0 requests leave the machine
in the test suite · cost 0 USD. No latency target: the time is the registries'. The PRD sets no
number for this feature.

## Out of scope
Deciding: the command prints facts and a verdict, the human approves (R10); nothing in the guard,
the runner or the gates runs it or requires its exit code. Age, repository, look-alike and OSV
measured on the private index (the simple API does not carry them, ADR-0014). An index declared
anywhere but `--index` and the three variables (`UV_EXTRA_INDEX_URL`, `[[tool.uv.index]]` in
`pyproject.toml`, `uv.toml`, `pip.conf`): none is read. Vulnerabilities by version: the OSV count
is for the package, every version together. Transitive dependencies, licences, maintainers,
download counts, ecosystems other than PyPI. Keeping `POPULAR_PACKAGES` current.

Limits that stay (ADR-0028): a token written in the path of an index URL is printed with the
path (the help of `--index` says so); a request abandoned at the deadline leaves its thread and
socket behind until the server stops sending or the process exits; a PEP 503 page without a
single file cannot be told from a login page and is verdict 2; a link text cut with another mark
than `..>` is not read from the href.

Not verified by any test: TLS certificate checking (`urllib` defaults); the transport of a
plain-`http` index without credentials, which the threat model accepts as a risk (only the
package name travels in clear); an OSV 404, which counts as no vulnerability. Tested on the
redirect rule only, not through a server (the tests have no local `https` server): `https` is
never left for plain `http`.

## Questions raised while writing the spec (for the human; behaviour today, not requirements)
- OSV out of reach leaves the verdict at 0 (R4): a package can pass with the vulnerability check
  skipped. Intended?
- With an index in use, the name of every package, private ones included, is still sent to
  `pypi.org` and, when PyPI knows it, to `api.osv.dev`; there is no switch to stay on the index.
- `pip` and `six` are within two edits of each other: `verify-dep pip` warns that it looks like
  `six`, and the reverse, so two popular packages get verdict 1.
