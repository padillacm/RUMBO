# F-0003: Tests cannot be weakened unnoticed
Story: As a developer who reviews the work of a coding agent I want every change that leaves the
tests weaker than the base to fail the check until I approve it myself, so that the agent cannot
reach green by deleting, skipping or hollowing tests.

Scope: `scripts/check_tests_not_weakened.py` (canonical source
`src/rumbo/sensors/check_tests_not_weakened.py`), the anti-cheat sensor. It runs as the `sensor`
step of the verification runner, in gate G4 and in CI with `--strict`, and as
`rumbo check-tests` where the CLI is installed.
Decisions: ADR-0007 (what counts as an assertion, helper resolution, the tests directory),
ADR-0008 and ADR-0021 (who counts as an agent when the approval mark is read), ADR-0026 (the
harness settings are read from the base) and ADR-0027 (what counts as a test that runs).
Written after the code: it describes the sensor as it is on 2026-11-21, not a plan.

## Requirements (EARS)
<!-- Ubiquitous: The system shall… · Event: When…, the system shall… · State: While…, the system shall…
     Unwanted: If…, then the system shall… · Optional: Where…, the system shall… -->
- R1 (ubiquitous): The sensor shall compare the files under the tests directory at the base commit, read from git with paths relative to `--root`, with the files under it in the working tree, read from disk whether committed or not, parsing the Python files without importing them, and likewise the `conftest.py` of every directory above it up to `--root`; the tests directory is `--tests-dir` alone when given, else `[tool.rumbo].tests` of `pyproject.toml` at the base commit, else `tests`; when the working tree gives another one, both are compared on both sides and the sensor shall report `[tool.rumbo].tests changed from 'OLD' to 'NEW': N file(s) of the base leave the tests directory (first: PATH)` as a problem when a file of the base is under the old one and not under the new one, else print the change as a `NOTE:`.
- R2 (ubiquitous): The sensor shall take as base the merge base of `HEAD` with the first of these that resolves to a commit: `--base`, `RUMBO_BASE_REF` (an all-zero SHA is skipped), `origin/` followed by `GITHUB_BASE_REF`, `origin/` followed by `RUMBO_DEFAULT_BRANCH`, `origin/main`, `origin/master`, `origin/HEAD`, `main`, `master` (the upstream of the branch is not one of them); for each of the first four that is set and does not resolve it shall print `WARNING: SOURCE 'REF' is not reachable; trying defaults`, SOURCE being `explicit base` or the name of the variable, and go on to the next ones, and it shall print `WARNING: base 'REF' is HEAD itself: nothing to compare` when the base is `HEAD` itself and was found through `RUMBO_DEFAULT_BRANCH` or one of the five default names.
- R3 (unwanted): If none of those resolves to a commit, then the sensor shall print `WARNING: no base to compare against (no origin/main?).` and exit 0, or exit 2 where `--strict` is given and `RUMBO_BASE_REF` is not the all-zero SHA of a new ref; and if, where `--strict` is given, the base earned the `HEAD itself` warning of R2 and the working tree holds no problem, then it shall print `ERROR: nothing to compare: the base found by default is HEAD itself.` and exit 2, unless `RUMBO_BASE_REF` is the all-zero SHA or `GITHUB_EVENT_NAME` is `workflow_dispatch` or `schedule` (`NOTE: nothing to compare: a EVENT run on the base itself.`), where it exits 0; work that is not committed is compared and reported whatever the base found.
- R4 (unwanted): If a file that is under the tests directory at the base is missing from the working tree (`test file deleted: PATH`), a test of the base, identified by its file path and qualified name, is missing from it (`test deleted or renamed: KEY`), goes under a statement of its module or class such as an `if`, a `try` or a `with` (`KEY: moved under a condition: review`) or leaves the module level and the classes pytest may collect (`KEY: no longer where pytest collects it: review`), the change adds to a file that reaches the base (see the invariants) a `del` of a test or collected class the base had (`PATH: test removed with del: NAME`), a second binding of its name (`PATH: test name bound again: NAME`) or `__test__` set to anything but a true constant or a dict in a module or on a class where the base had tests (`PATH: __test__ set to a false value`), adds to a test or collected class of both sides a decorator that is a function, a class or a lambda written in the tests directory (`KEY: decorator added: review (@NAME [defined in the tests])`), or a Python file of the working tree cannot be parsed and it parsed at the base or is new (`parse error: PATH: cannot parse (REASON)`) or it changed (the same line plus `: changed, and this Python cannot parse it at the base either`), then the sensor shall report each as a problem; a test is every function, plain or `async`, whose name starts with `test`, wherever it is written outside another test, and every such function that a class pytest may collect inherits from a class of the tests directory; not problems: an added file, test or class by itself, a file that parses on neither side and did not change (a `NOTE:`), a byte-order mark, a submodule, and a symbolic link, which is one entry as in git.
- R5 (unwanted): If a test has fewer assertions than at the base in either of its two counts, those able to fail (`KEY: asserts dropped from A to B`) or, when that count did not drop, those written (the same line plus `, counting those that cannot fail`), or the compared files as a whole have fewer written ones (`total asserts in the tests directory dropped from A to B`; the total is the written count of every test where it is written plus the assertions outside the tests that no test reaches through a helper), then the sensor shall report it with both numbers.
- R6 (unwanted): If a test has more always-true assertions than at the base, an `assert` on a truthy constant or on a non-empty tuple, then the sensor shall report `KEY: gained always-true asserts (assert True / tuple)`.
- R7 (unwanted): If a test has more skip forms than at the base, then the sensor shall report `KEY: gained skip/skipif/xfail markers or pytest.skip() calls`, counting the marks of `SKIP_MARKS` in its decorators (also inside `pytest.param(..., marks=...)` and behind a name of the tests directory that stands for a decorator), a decorator whose last name is in `SKIP_NAMES`, and, in its body, in a helper it resolves (R10) and in the body of each fixture it uses (by parameter or by `usefixtures`, and the fixtures those take, three levels deep), each such mark, each call of `SKIP_CALLS` (`pytest.skip`, `pytest.xfail`, `pytest.importorskip`, `pytest.exit`) under the name the module imported it, each call to a method named `skipTest` and each `raise` of `SkipTest`; it shall report the same line for a class pytest may collect, present on both sides, that gains one in its decorators, its `pytestmark` or a method of `SETUP_METHODS`, `PATH: skip/xfail forms outside the tests grew from A to B` for a file that reaches the base and gains one in a statement of the module, in `setup_module`, in `setup_function` or in an autouse fixture, and `PATH: conftest hook added: review (NAME)` for a hook of `REVIEW_HOOKS` added to a `conftest.py` that reaches the base (`PATH: pytest hook added: review (NAME)` in any other module, when the base had another Python file that is neither a `conftest.py` nor an `__init__.py`); a new test, a new class and a new file that does not reach the base carry their own skips.
- R8 (unwanted): If the number of literal `parametrize` cases of a test is lower than at the base, then the sensor shall report `KEY: parametrize cases dropped from A to B`; the number is the product, over its `parametrize` decorators (also behind a name of the tests directory that stands for one), of the elements of the list or tuple literal passed as second positional argument or as `argvalues=`, where a starred list, tuple or set literal counts its own elements (`*()` none) and any other element counts one.
- R9 (ubiquitous): The sensor shall count as one assertion each `assert` statement, each `pytest.raises`, `pytest.warns` or `pytest.deprecated_call` item of a `with`, each call to `self.fail`, to `pytest.fail` or to a method of `self` whose name starts with `assert`, and each call to one of the fourteen `unittest.mock` assertion methods by exact name (`MOCK_ASSERT_NAMES`) on a receiver written as a name or an attribute; any other statement or call that R10 does not resolve counts zero; in the count of the assertions able to fail (R5) it shall leave out those under a nested function or class without a decorator, or a lambda bound to one name, whose name the test or helper that holds it never reads again, in the body of a `try` with a handler for `AssertionError`, `Exception`, `BaseException` or everything that holds only `pass`, constants or a `continue` with no assertion after the `try`, and under a `with suppress(...)` naming one of those three, and count zero for a test that yields and is not a fixture.
- R10 (ubiquitous): The sensor shall count a call to a helper as the assertions of the helper's body under the same rules when the helper is a function defined at the top level of the same file, of a `conftest.py` of the same directory or of an ancestor, or of a module imported from inside the tests directory, or a method called as `self.name()`, `cls.name()` or `Class.name()` that belongs to the test's class or to a base class defined or imported inside the tests directory; it shall follow at most three helper calls from the test, and a call back into a helper already being counted counts zero; in the count of the assertions able to fail (R5) a call counts zero where R9 leaves an assertion out, and so does a call that is a statement by itself to a helper that is a generator or an `async def`.
- R11 (ubiquitous): The sensor shall print every problem it found, one `  - ` line each under `Tests weakened relative to BASE:`, or `OK: no test weakened relative to BASE.`, and exit 0 when there is none, 1 when there is at least one and no human approved the change, and 2 on a usage error, in the `--strict` cases of R3, and when git cannot list the files of the base or read one of its Python files (an `ERROR: cannot` line, and nothing is compared).
- R12 (event): When problems are found and a human approved the change, by the label `tests-change-approved` on the pull request described in the file `GITHUB_EVENT_PATH` names, read only where `GITHUB_ACTIONS` is `true` and `GITHUB_EVENT_NAME` starts with `pull_request`, or by a commit in `base..HEAD` whose message contains `[tests-change-approved]`, the sensor shall still list the problems, name the approval (`Approved by a human: REASON.`) and exit 0; it shall read the commits with NUL separators and take an event file that is missing or malformed as no label.
- R13 (unwanted): If an agent took part in the commit that carries the mark, because its author, its committer or the value of a `Co-authored-by:` trailer contains, whatever the case, an identity of `DEFAULT_AGENT_AUTHORS`, of `[tool.rumbo].agent_authors` at the base commit or of the same list in the working tree, or its message contains one of `DEFAULT_AGENT_TRAILERS`, then the sensor shall ignore that mark and say which commit it ignored (`(ignoring [tests-change-approved] in SHA: commit authored by an agent)`).
- R14 (ubiquitous): The sensor shall import the standard library only, be copied unchanged into every generated project, and be reachable as `rumbo check-tests`, which passes its arguments on and returns the sensor's exit code.

## Data contracts and ownership
<!-- What two sessions (or two agents) must agree on BEFORE writing code. Omitting explicit data
     structures is what breaks parallel work (docs/method.md, section 3.1). -->
- Types / schemas: `TestInfo(asserts: int, constant_asserts: int, skips: int, param_cases: int | None, decorators: tuple[str, ...], lexical: int, conditional: bool, collected: bool)`, where `asserts` is the count able to fail and `lexical` the written one, and `param_cases` is `None` when no `parametrize` decorator has a literal list; `ClassInfo(decorators: tuple[str, ...], skips: int)`; `Inventory(files: set[str], tests: dict[str, TestInfo], asserts: int, errors: list[str], unparsed: dict[str, str], unparsed_text: dict[str, str], classes: dict[str, ClassInfo], outside_skips: dict[str, int], flags: dict[str, Counter[tuple[str, str]]], links: set[str])`, whose `tests` and `classes` keys (KEY in the requirements) are `path::Qualified.name` with POSIX paths relative to `--root`, `classes` holding only the classes pytest may collect; `SensorError(RuntimeError)`, raised by `base_inventory` when the base cannot be read; `[tool.rumbo].tests: str` and `[tool.rumbo].agent_authors: list[str]` in `pyproject.toml` (a value of another type is ignored, as are blank entries and entries that are not strings); the GitHub event file, a JSON object read only at `pull_request.labels[].name`.
- Signatures: `main(argv: list[str] | None = None) -> int` with the options `--base REF`, `--root DIR` (default `.`), `--strict`, `--tests-dir DIR`; `analyze(files: Mapping[str, str | None]) -> Inventory` (path to content, `None` for a file that is not Python); `compare(base: Inventory, current: Inventory) -> list[str]` and `notes(base: Inventory, current: Inventory) -> list[str]`; `tests_directory(root, override=None) -> str` (the working tree's) and `tests_directories(root, base, override=None) -> list[str]` (the directories of R1); `base_inventory(base, root, tests_dir="tests") -> Inventory` and `worktree_inventory(root, tests_dir="tests") -> Inventory` (one directory or several); `resolve_base(explicit: str | None, root) -> tuple[str | None, list[str]]` (base commit or `None`, warnings); `agent_authors(root, base=None) -> tuple[str, ...]`; `human_approval(base: str, root) -> str | None` (the reason, or `None`). Environment variables read: `RUMBO_BASE_REF`, `GITHUB_BASE_REF`, `RUMBO_DEFAULT_BRANCH`, `GITHUB_EVENT_NAME`, `GITHUB_ACTIONS`, `GITHUB_EVENT_PATH`.
- Shared invariants: exit 0 means not weakened, approved by a human, or nothing to compare (R3); exit 1 means weakened and not approved; exit 2 means a usage error, a base that cannot be read, or one of the `--strict` cases of R3. The sensor prints on standard output (the argument parser writes its usage error on standard error) and decodes git's output as UTF-8. Each problem line is quoted in the requirement that reports it (R1, R4 to R8). `APPROVAL_MARK` is `[tests-change-approved]`, the same string the guard refuses from an agent; `APPROVAL_LABEL` is `tests-change-approved`. The label is looked at before the commits, and one approval covers every problem of the run. `[tool.rumbo].agent_authors` adds to `DEFAULT_AGENT_AUTHORS`, it never replaces it, and the working tree adds to the list of the base, it never removes from it. Two definitions of a test under one qualified name are compared by the weaker of each number. pytest may collect a class when its name starts with `Test`, or when one of its bases other than `object` is a class the sensor cannot find in the tests directory or one that pytest may collect, provided the class is not inside a function or inside a class that pytest may not collect. A file reaches the base when it was at the base; a `conftest.py` and an `__init__.py`, new or not, reach it instead when a Python file of the base other than those two is in their directory or below. Both sides of the comparison are analysed with the same rules, each on its own.
- Files owned by this spec (one writer): `src/rumbo/sensors/check_tests_not_weakened.py`, `tests/test_sensor.py`, `src/rumbo/templates/tests/unit/test_check_tests_not_weakened.py`, and the dispatch of `check-tests` in `src/rumbo/cli.py`. `scripts/check_tests_not_weakened.py` is a copy that `rumbo update` refreshes; `tests/unit/test_check_tests_not_weakened.py` is a copy of the template that `rumbo update` does not refresh (it is not in `FRAMEWORK_OWNED`).
- Interfaces touched that other specs depend on: the guard protects the script and refuses the mark from an agent (F-0001); the `sensor` step of `[tool.rumbo.checks]` calls the script with `--base {base}` (F-0002); `init`, `--adopt` and `update` copy the script, and the generated CI workflow runs it with `--strict`, `RUMBO_BASE_REF` and `RUMBO_DEFAULT_BRANCH` (F-0004); gate G4 runs it with `--strict` and the base it measured, and `rumbo metrics` counts the commits that carry the mark (F-0005).

## NFR
0 dependencies (R14) · 0 network calls: the only subprocesses are local git commands
(`rev-parse`, `merge-base`, `ls-tree`, `show`, `log`) · cost 0 USD. No latency target is set: the
cost is one `git show` per Python file of the base and at most two for its `pyproject.toml`, plus

20,000 tests.

## Out of scope
What the sensor does not see, by its own account: an early `return` before the asserts, asserts
under a condition that is false, a handler that swallows the failure after doing something, mocks
that empty the behavior, mock assertions on a fresh mock, a widened `pytest.raises`, helpers
built dynamically or imported from outside the tests directory, changes to
`[tool.pytest.ini_options]`. Review these by hand; mutation testing covers part of them.

Checked against the code and also not detected (the limits ADR-0027 states are among them):
- a `parametrize` whose values are not a literal list or tuple, and the removal of the decorator;
- an assertion that is always true without being a constant or a tuple (`assert x or True`), one whose expression was made weaker, and a `self.assert*` method that checks nothing (it counts one, R9);
- a nested function mentioned once and never run, a generator helper whose result is kept and never iterated, a decorator from a library or from the package under test that replaces the test, and dynamic tricks (`globals()`, `setattr`, `delattr`);
- tests under other prefixes than `test` and `Test`, where the project sets `python_functions` or `python_classes`: the total alone protects them;
- the push after the push that weakened: on a `push` run the base is the commit before the push, so once a weakening is on the default branch, the next push is compared with it and passes;
- the push run after a pull request approved by label: the label is read only in a pull request run (R12), so the run on the default branch reports the weakening again, as it does when the squash commit carries an agent's `Co-authored-by:` trailer next to the mark (R13);
- weakening already committed where the base is `HEAD` and `--strict` is not given: the sensor warns (R2) and compares only what is not committed;
- who added the label: the sensor checks the commits for agents, not the label;
- which problem an approval is for: a mark anywhere in `base..HEAD` approves the whole run.

Not stated as requirements because no test covers them: a base ref that shares no history with
`HEAD` (the code then compares against the ref itself), a tests directory that leaves the
repository (git refuses the path and the run exits 2), and a machine without git (the code does
not catch the missing executable).

The purity rules for `domain/` that ADR-0007 also decides belong to the architecture test of the
generated project, not to the sensor.

## Questions open before signing
- Stated above from the code, with no test in `tests/test_sensor.py`: `argvalues=` (R8);
  `pytest.exit`, `setUpClass`, `asyncSetUp`, `setup_class`, `usefixtures` in the `pytestmark` of
  a class and the third level of fixtures (R7); the `HEAD itself` warning through
  `RUMBO_DEFAULT_BRANCH` (R2); `m().assert_called()`, which counts zero (R9).
- ADR-0007 counts mock assertions "on any receiver"; the code counts them on a receiver written
  as a name or an attribute (R9). Which one is meant?
- ADR-0027 and the code differ in four details: a plugin hook is reported "when the base had
  tests" (code: any other Python file but a `conftest.py` or an `__init__.py`); a new ref exits
  0 "with a note" (code: with a default base that is `HEAD`, the warning of R2 and `OK` only);
  "an unreachable candidate earns a warning" (code: the four named ones); a base that is not in
  the clone "stays exit 2" (code: the default names are tried first, R2 and R3).
- ADR-0007 keeps "the per-file total" among the unchanged rules; the code keeps one total for the
  whole tests directory (R5). Which one is meant?
- Helper methods of the test class (R10) are in the code, the tests and the changelog, but the
  text of ADR-0007 only describes calls to a bare name or to `module.name`.
- `test_configured_tests_directory_is_honoured_end_to_end` here, and `test_end_to_end_with_git` in
  the tests shipped to every project, expect exit 1 without clearing the variables of a CI run:
  in a pull request run of GitHub Actions that carries the label they get 0 and fail.
