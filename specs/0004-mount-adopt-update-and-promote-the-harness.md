# F-0004: Mount, adopt, update and promote the harness
Story: As a developer who starts or inherits a Python project that a coding agent will work on
I want one command that mounts the RUMBO harness, and later refreshes it or raises its rigor, so
that the guides, sensors and gates are in place and current without my code or my documents
being overwritten.

Scope: `rumbo init` (with `--adopt`, `--force`, `--python`, `--types`, `--no-install`),
`rumbo update` (with `--diff`) and `rumbo promote`: `src/rumbo/scaffold.py`,
`src/rumbo/render.py`, `src/rumbo/project.py`, those three subcommands in `src/rumbo/cli.py` and
the templates under `src/rumbo/templates/`. Written after the code (v0.4): it describes what the
branch does today.
Decisions: ADR-0001, ADR-0002, ADR-0010, ADR-0011, ADR-0013, ADR-0014, ADR-0015, ADR-0020,
ADR-0021.

## Requirements (EARS)
<!-- Ubiquitous: The system shall… · Event: When…, the system shall… · State: While…, the system shall…
     Unwanted: If…, then the system shall… · Optional: Where…, the system shall… -->
- R1 (unwanted): If the configuration given to `rumbo init` is incomplete or invalid (a project name that is empty, longer than 80 characters or holds a double quote, a backslash or a control character; a package that is not a snake_case identifier, is a Python keyword or is one of `test`, `tests`, `src`, `evals`, `scripts`, `spikes`, `domain`, `app`, `api`; with `--yes`, no `--llm`/`--no-llm` or no `--rigor`; an LLM product without a known provider, or provider `other` without a valid SDK package, module and environment variable), then the system shall refuse it with exit code 2 before writing a file; a name it accepts shall be embedded in TOML and Python as an escaped string, and a package that is not given shall be derived from the name in snake_case.
- R2 (ubiquitous): The CLI shall import nothing outside the Python standard library and its own package, and shall render its templates with its own engine: `{{var}}` is substituted, `{{#flag}}` and `{{^flag}}` sections keep or drop a block, a section tag alone on its line leaves no blank line, `${{ expr }}` is left untouched, a substituted value is never expanded again, and an unknown variable, an unknown section, an unbalanced tag or a section nested in itself raises `TemplateError`; in a target path `__pkg__` becomes the package, a leading `dot_` becomes `.` and the `.tmpl` suffix is dropped.
- R3 (ubiquitous): The system shall generate, on top of the common harness, what the kind of the project calls for and nothing of the other kinds: `service` (the default) gets the HTTP skeleton (`api/http.py`, `tests/integration/test_http.py`), `infra/Dockerfile`, `docs/ops/runbook.md` and `docs/ops/slos.md`, with `fastapi`, `uvicorn` and `httpx` as runtime dependencies whether or not it calls a model; `library` and `cli` get `CHANGELOG.md`, `.github/workflows/release.yml` and a package that exposes its version, and `cli` also `[project.scripts]`; `data` gets `infra/Dockerfile`, the runbook and offline evals (`evals/`, `docs/evals/plan.md`), with a `pipeline.py` entry when it calls no model; every kind gets the package's `__init__.py` and `__main__.py`.
- R4 (ubiquitous): The system shall organise the package by its layout: `hexagonal` (the default of a service, and of every LLM product whatever `--layout` says) with the packages `api`, `adapters`, `app` and `domain`; `layered` with one package per name of `--layers` (two or more distinct snake_case names, outermost first); `flat` (the default of a library, a cli and a data project) with no layer package. With layers it shall render the import-linter layers contract in that order and a purity contract on the innermost layer, make that layer the strict target of the type checker and the mutation target, and add the `arch` step and the `import-linter` tool; a flat layout has none of them. An unknown kind or layout, or `layers` that do not fit the layout, shall be refused.
- R5 (optional): Where the project calls an LLM (`--llm` with a provider among `anthropic`, `openai`, `google`, `mistral`, `claude-code`, or `other` with its SDK settings), the system shall add the model skeleton (`prompts/`, `app/entrypoint.py`, `app/ports.py`, `app/budget.py`, `app/telemetry.py`, `adapters/llm.py`, `.env.example`), the evals with the judge grader and its calibration set, `pydantic` and the provider SDK as runtime dependencies, and the SDK module among the imports forbidden in the domain layer; provider `claude-code` installs no SDK and adds `adapters/claude_code.py`; the model credential is named in `nightly.yml` and never in `ci.yml`.
- R6 (ubiquitous): The system shall scale the harness with the rigor: every project gets `ruff`, the type checker, `pytest`, `hypothesis` and `pre-commit` as development tools (plus `import-linter` when the layout is not flat) and the steps `lint`, `format`, `types`, `test`, `arch` (layout not flat), `evals` (LLM and data projects) and `sensor`, in that order; from `mvp` it adds `pytest-cov`, `bandit` and `pip-audit`, coverage in the `test` step, the steps `security`, `security-scripts` and `audit` after `arch`, and the files `.github/workflows/nightly.yml` and `.github/dependabot.yml`; `production` adds `mutmut`; no tool is written with a version.
- R7 (ubiquitous): The system shall write every file it creates, merges or updates in UTF-8 with LF line endings on every platform, shall turn the CRLF of a source file into LF, and shall generate a `.gitattributes` that keeps the checkout in LF (`* text=auto eol=lf`).
- R8 (unwanted): If a file of the plan already exists in the project, then `rumbo init` shall leave it untouched and list it as skipped, except `pyproject.toml`, which only gains the `[tool.*]` sections it lacks (its own sections are kept, and `[tool.hatch]` is added only when the build backend is hatchling), and `.gitignore`, which only gains the lines it lacks; with `--force` the other existing files are overwritten after a `.bak` copy is kept, and those two are still merged, never replaced.
- R9 (event): When `rumbo init --adopt` runs on an existing directory, the system shall detect, and use where no flag says otherwise: the package (`[project].name` in snake_case when it is a package under `src/` or at the root, else the only directory with an `__init__.py` there that is not `tests`, `test`, `docs`, `scripts`, `spikes`, `evals`, `infra` or `src`), where the package lives (`src` or `.`), the kind (`cli` with console scripts, else `service` with `fastapi`, `flask`, `django` or `starlette` among the dependencies, else `library`), the layout (`hexagonal` when the package has `domain/` and `app/`, else `flat`) and the tests directory (`tests`, else `test`, else `tests`); it shall show them as the defaults of the interactive questions, and shall refuse with exit code 2 two or more candidate packages without `--package`, and a directory that does not exist.
- R10 (event): When `rumbo init --adopt` mounts the harness, the system shall write no file under `src/` or inside the package and, under the tests directory, only `architecture/test_architecture.py` and `unit/test_check_tests_not_weakened.py`; shall record `adopted = true`, `src` and (only when it is not `tests`) `tests` in `[tool.rumbo]` and point the paths of every tool at the package and the tests directory it found; shall run the `lint`, `format` and `types` steps on `{changed}`; shall not write `ci.yml` when `.github/workflows/` already holds a workflow, printing instead the two steps to add to it; and shall not write `infra/` when that directory exists. Without `--adopt` none of this applies.
- R11 (event): When `rumbo update` runs, the system shall replace the files the framework owns with their current version (`RUMBO.md`, the three scripts under `scripts/`, the `0000-template.md` of ADRs, specs and postmortems, `spikes/README.md`, `.claude/commands/`), create the ones that are missing together with any missing `.claude/` file and the files the rigor brings (`nightly.yml`, `dependabot.yml`), list the other harness files that differ from the current template without changing them, and leave every other file as it is; in `pyproject.toml` it shall only append the `[tool.rumbo.checks]` table or the steps of the current rigor the table lacks (never replacing or removing a step), add the keys `kind`, `layout`, `types`, `python` and `src` that are missing, and set `[tool.rumbo].version` to the version of the CLI; it shall print the `uv add --dev` line for the development tools of the level that the project does not list.
- R12 (optional): Where `rumbo update` is given `--diff`, the system shall write nothing and print, for each harness file that differs from the current template, a unified diff headed by what `update` would do with it (`[update replaces]`, `[merge by hand]`, or `[missing; copy by hand if wanted]`), leaving out the documents the human edits, `pyproject.toml`, `.gitignore` and the `rev:` lines of `.pre-commit-config.yaml`; with nothing to show it shall print `Everything matches the current templates.`
- R13 (event): When `rumbo promote` names a rigor above the current one, the system shall rewrite only the `rigor` key of `[tool.rumbo]`, run the update of R11 for the new level and run `uv add --dev` with the tools of the level the project does not list yet (with `--no-install` it prints that line instead); it shall remove or replace nothing (steps, files, `AGENTS.md`, the Makefile), and shall refuse an equal or lower rigor with exit code 1 and `pyproject.toml` unchanged.
- R14 (optional): Where `rumbo init` is given `--python` (3.11, 3.12 or 3.13; default 3.11), the system shall store it as `[tool.rumbo].python` and render it in `requires-python`, the `target-version` of ruff, the CI matrix of a library or cli (that version and the newer supported ones), the Dockerfile and `.python-version`; where it is given `--types mypy` (default `pyright`), it shall store `[tool.rumbo].types`, list `mypy` instead of `pyright` among the development tools, make `uv run mypy` the `types` step and render `[tool.mypy]` instead of `[tool.pyright]`, with the innermost layer strict; any other value of either is refused with exit code 2 and nothing is written.
- R15 (unwanted): If an agent marker is set in the environment (`[tool.rumbo].agent_env`, else the default markers of the guard) or the command does not run at a real terminal (standard input and output; on Windows the null device is not one), then `rumbo init` shall not run `git config rumbo.human true`: it shall leave the setting as it is and print that command among its next steps while the clone does not declare it. Only for a human at a terminal, in a git repository and after installing the git hooks, does `rumbo init` run the command itself.

- Types / schemas: `[tool.rumbo]` in `pyproject.toml`, the stored state of a project: `version: str` (the harness version), `name: str`, `package: str`, `kind: "service" | "library" | "cli" | "data"` (absent means `service`), `layout: "hexagonal" | "layered" | "flat"` (absent means the default of the kind), `layers: list[str]` (only with `layered`), `llm: bool`, `provider: str` (`"none"` without a model), `sdk_package`, `sdk_module`, `sdk_env_key: str`, `rigor: "prototype" | "mvp" | "production"` (absent means `mvp`), `python: "3.11" | "3.12" | "3.13"` (absent means `3.11`), `types: "pyright" | "mypy"` (absent means `pyright`), `src: "src" | "."` (absent means `src`), `adopted: bool` and `tests: str` (written only by adoption; absent means `false` and `tests`); `[tool.rumbo.checks]` is an ordered table of step name to command. `Config` (what is rendered) and `Project` (what is read back) carry the same fields, and `Config.from_project(Project.load(root))` plans the same set of files as the `Config` that mounted it (`case` is not stored). `Report` lists `created`, `skipped`, `merged`, `updated`, `differs`, `commands` (command, exit code), `suggested` and `notes`.
- Signatures: `Config(name, package, llm, provider="", rigor="mvp", case="", sdk_package="", sdk_module="", sdk_env_key="", kind="service", layout="", layers=(), adopted=False, tests_dir="tests", python="3.11", types="pyright", src="src")` raises `ValueError`; `plan_files(cfg, root=None) -> dict[str, str | Path]` (target path to rendered text, or to a file copied as it is); `scaffold(cfg, dest, force=False) -> Report`; `install(cfg, dest, report, human=None) -> None`; `human_present(dest, environ=None, isatty=None) -> bool`; `detect_project(root, package=None) -> Detected` raises `ValueError` on an ambiguous package; `update(project, dest) -> Report`; `update_diff(project, dest) -> str`; `set_rigor(text, rigor) -> str` raises `ValueError`; `dev_dependencies(cfg)`, `runtime_dependencies(cfg)`, `check_steps(cfg) -> list[str]`; `Project.load(root) -> Project` raises `FileNotFoundError` or `ValueError`; `render(text, ctx) -> str` raises `TemplateError` (a `KeyError`).
- Shared invariants: exit codes are 0 done, 2 refused before anything is written (invalid configuration, or no RUMBO project for `update` and `promote`), 1 when `promote` is asked for an equal or lower rigor or when an install command of `init` or `promote` failed; a template tag never reaches a generated file, and a section that is dropped is not validated; `pyproject.toml` and `.gitignore` are merged, never replaced; `update` only adds to `[tool.rumbo]` and `[tool.rumbo.checks]` and writes each late key once; the three scripts under `scripts/` are copies of `src/rumbo/sensors/` and are never edited in a project; the generated project never imports `rumbo`; the development tools and the check steps of a level come from one place each (`dev_dependencies`, the rendered `[tool.rumbo.checks]`), shared by `init`, `update` and `promote`.
- Files owned by this spec (one writer): `src/rumbo/scaffold.py`, `src/rumbo/render.py`, `src/rumbo/project.py`, the `init`, `update` and `promote` subcommands of `src/rumbo/cli.py`, `src/rumbo/templates/` (except the hook entries owned by F-0001), `tests/test_scaffold.py`, `tests/test_render.py`, the `init`, `update` and `promote` tests of `tests/test_cli.py`.
- Interfaces touched that other specs depend on: the guard's `agent_env_names` decides R15 (F-0001); `[tool.rumbo.checks]`, `{base}` and `{changed}` are read by the runner (F-0002); `[tool.rumbo].tests` and the copied sensor (F-0003); `Project` and `plan_files` are read by `gate`, `trace` and `doctor` (F-0005).

## NFR
`rumbo init --no-install` < 2 s (PRD; each scaffold test that runs it takes under 1 s on a

## Out of scope
Monorepos and uv workspaces; a package directory other than `src/` or the root; lowering the
rigor (a hand edit of `[tool.rumbo].rigor`); removing a step, a tool or a file a level brought;
a baseline file of accepted findings (ADR-0013); `ty` as a type checker (ADR-0015); a new A0
question for layout, Python or type checker (flags only). What the copied scripts do is F-0001
(guard), F-0002 (runner, `{changed}`) and F-0003 (sensor); `doctor` and the gates are F-0005.
Not stated as requirements because no test verifies them: the confirmation question of an
interactive `rumbo init` in a directory that is not empty; the refusal when standard input is
not a terminal and `--yes` is missing; the real `uv add` and `pre-commit install` of the
installing path (the tests replace `uv`); that every generated Python file passes ruff, ruff
format and the type checker (that is the e2e matrix, not pytest).

## Questions raised while drafting (for the human, before signing)
- `__main__.py` is generated for every kind and layout, a library and a flat package included
  (no entry in `CONDITIONS`; `test_each_kind_generates_exactly_its_column` asserts it). ADR-0010
  gives a library `__init__` only and says a flat layout has "`src/<pkg>/__init__.py` only". R3
  states what the code does.
- `rumbo init` asks for standard input and standard output to be terminals (`at_a_terminal`);
  ADR-0021 says "standard input is a terminal". The code is the stricter one; R15 states it.
- An LLM or data project has the `evals` step at `prototype` too; the prototype list of
  ADR-0011 does not name it. R6 states what the template renders.
- A layered project whose `layers` key is missing does not load, so `rumbo update` cannot write
  that key back (`test_update_writes_layers_for_a_layered_project` shows it); R11 leaves
  `layers` out of the late keys. ADR-0010 says the loader "never fails on their absence".
- `scripts/e2e.sh` (line 37) expects `rumbo.human` to be `true` after `rumbo init --yes`. Since
  ADR-0021 that only holds when the script is run by a human at a terminal (R15); the script was
  last changed before that decision, and CI has no terminal. Not run while drafting this spec.
