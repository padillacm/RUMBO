# F-0004: Mount, adopt, update and promote the harness
Story: As a developer who starts or inherits a Python project that a coding agent will work on
I want one command that mounts the RUMBO harness, and later refreshes it or raises its rigor, so
that the guides, sensors and gates are in place and current without my code or my documents
being overwritten.

Scope: `rumbo init` (with `--adopt`, `--force`, `--python`, `--types`, `--no-install`),
`rumbo update` (with `--diff`, `--allow-downgrade`) and `rumbo promote`: `src/rumbo/scaffold.py`
(with `guard_wiring`, which `rumbo doctor` prints), `src/rumbo/render.py`,
`src/rumbo/project.py`, those three subcommands in `src/rumbo/cli.py` and the templates under
`src/rumbo/templates/`. Written after the code (v0.4): it describes what the branch does on
2026-11-21.
Decisions: ADR-0001, ADR-0002, ADR-0010, ADR-0011, ADR-0013, ADR-0014, ADR-0015, ADR-0020,
ADR-0021, ADR-0029.

## Requirements (EARS)
<!-- Ubiquitous: The system shall… · Event: When…, the system shall… · State: While…, the system shall…
     Unwanted: If…, then the system shall… · Optional: Where…, the system shall… -->
- R1 (unwanted): If the configuration given to `rumbo init` is incomplete or invalid (a project name that is empty, longer than 80 characters or holds a double quote, a backslash or a control character; a package of a new project that is not a snake_case identifier, is a Python keyword, is one of `test`, `tests`, `src`, `evals`, `scripts`, `spikes`, or is one of `domain`, `app`, `api` when its kind and layout write a sub-package of that name; a package of an adopted project that is not a Python identifier, is a keyword, or lives at the root under one of those six names; no `--yes` when standard input is not a console (`is_console`); with `--yes`, no `--llm`/`--no-llm` or no `--rigor`; an LLM product without a known provider, or provider `other` without a valid SDK package, module and environment variable), then the system shall refuse it with exit code 2 before writing a file; a name it accepts shall be embedded in TOML and Python as an escaped string, and a package that is not given shall be derived from the name in snake_case.
- R2 (ubiquitous): The CLI shall import nothing outside the Python standard library and its own package, and shall render its templates with its own engine: `{{var}}` is substituted, `{{#flag}}` and `{{^flag}}` sections keep or drop a block, a section tag alone on its line leaves no blank line, `${{ expr }}` is left untouched, a substituted value is never expanded again, and an unknown variable, an unknown section, an unbalanced tag or a section nested in itself raises `TemplateError`; in a target path `__pkg__` becomes the package, a leading `dot_` becomes `.` and the `.tmpl` suffix is dropped.
- R3 (ubiquitous): The system shall generate, on top of the common harness, what the kind of the project calls for and nothing of the other kinds: `service` (the default) gets the HTTP skeleton (`api/http.py`, `tests/integration/test_http.py`), `infra/Dockerfile`, `docs/ops/runbook.md` and `docs/ops/slos.md`, with `fastapi`, `uvicorn` and `httpx` as runtime dependencies whether or not it calls a model; `library` and `cli` get `CHANGELOG.md`, `.github/workflows/release.yml` and a package that exposes its version, and `cli` also `[project.scripts]`; `data` gets `infra/Dockerfile`, the runbook and offline evals (`evals/`, `docs/evals/plan.md`), with a `pipeline.py` entry when it calls no model; every kind gets the package's `__init__.py` and `__main__.py`.
- R4 (ubiquitous): The system shall organise the package by its layout: `hexagonal` (the default of a service, and of every LLM product whatever `--layout` says) with the packages `api`, `adapters`, `app` and `domain`; `layered` with one package per name of `--layers` (two or more distinct snake_case names, outermost first); `flat` (the default of a library, a cli and a data project) with no layer package. With layers it shall render the import-linter layers contract in that order and a purity contract on the innermost layer, make that layer the strict target of the type checker and the mutation target, and add the `arch` step and the `import-linter` tool; a flat layout has none of them. An unknown kind or layout, or `layers` that do not fit the layout, shall be refused.
- R5 (optional): Where the project calls an LLM (`--llm` with a provider among `anthropic`, `openai`, `google`, `mistral`, `claude-code`, or `other` with its SDK settings), the system shall add the model skeleton (`prompts/`, `app/entrypoint.py`, `app/ports.py`, `app/budget.py`, `app/telemetry.py`, `adapters/llm.py`, `.env.example`), the evals with the judge grader and its calibration set, `pydantic` and the provider SDK as runtime dependencies, and the SDK module among the imports forbidden in the domain layer; provider `claude-code` installs no SDK and adds `adapters/claude_code.py`; the model credential is named in `nightly.yml` and never in `ci.yml`.
- R6 (ubiquitous): The system shall scale the harness with the rigor: every project gets `ruff`, the type checker, `pytest`, `hypothesis` and `pre-commit` as development tools (plus `import-linter` when the layout is not flat) and the steps `lint`, `format`, `types`, `test`, `arch` (layout not flat), `evals` (LLM and data projects) and `sensor`, in that order; from `mvp` it adds `pytest-cov`, `bandit` and `pip-audit`, coverage in the `test` step, the steps `security`, `security-scripts` and `audit` after `arch`, and the files `.github/workflows/nightly.yml` and `.github/dependabot.yml`; `production` adds `mutmut`; no tool is written with a version.
- R7 (ubiquitous): The system shall write every file it creates, merges or updates in UTF-8 with LF line endings on every platform (`write_text`; `rumbo new`, `rumbo decision`, `rumbo eval add` and `rumbo tour --out` write LF too), shall turn the CRLF of a source file into LF, and shall generate a `.gitattributes` that keeps the checkout in LF (`* text=auto eol=lf`).
- R8 (unwanted): If a file of the plan already exists in the project, then `rumbo init` shall leave it untouched and list it as skipped, except `pyproject.toml`, which only gains the `[tool.*]` sections it lacks (its own sections are kept, `[tool.hatch]` is added only when the build backend is hatchling, and a missing `[build-system]` is reported with one that fits, never added), and `.gitignore`, which only gains the lines it lacks; with `--force` an existing file whose bytes equal what would be written is listed as unchanged, and any other is overwritten after a copy under the first free name among `.bak`, `.bak.1`, `.bak.2` and so on (a backup is never overwritten; no copy is made when a backup met on the way holds the same bytes), while those two are still merged, never replaced; a symbolic link where a file of the plan goes is skipped, never followed nor replaced. `rumbo init` shall read, merge and validate everything before it writes anything, and shall refuse with exit code 2, naming the file and leaving the directory as it was: a target that is a file, a file where the harness needs a directory or a directory where it writes a file, a `pyproject.toml` or `.gitignore` that is not UTF-8 (a byte order mark is accepted), a `pyproject.toml` that is not valid TOML before or after the merge, and an existing `[tool.rumbo]` without `package`.
- R9 (event): When `rumbo init --adopt` runs on an existing directory, the system shall detect, and use where no flag says otherwise: the package (`[project].name` in snake_case when it is a package under `src/` or at the root, else the only directory with an `__init__.py` there that is not `tests`, `test`, `docs`, `scripts`, `spikes`, `evals`, `infra` or `src`; always with the spelling its directory has on disk, such as `MyPkg`), where the package lives (`src` or `.`), the kind (`cli` with console scripts, else `service` with `fastapi`, `flask`, `django` or `starlette` among the dependencies, else `library`), the layout (`hexagonal` when the package has `domain/` and `app/`, else `flat`) and the tests directory (`tests`, else `test`, else `tests`); it shall show them as the defaults of the interactive questions, and shall refuse with exit code 2, writing nothing, two or more candidate packages without `--package`, a directory that does not exist, and a package that is not a directory under `src/` or at the root (a `--package` that names none; a project of single modules, which the message lists).
- R10 (event): When `rumbo init --adopt` mounts the harness, the system shall write no file under `src/` or inside the package and, under the tests directory, only `architecture/test_architecture.py` and `unit/test_check_tests_not_weakened.py`; shall record `adopted = true`, `src`, `own_ci`, `own_infra` and (only when it is not `tests`) `tests` in `[tool.rumbo]` and point the paths of every tool at the package and the tests directory it found; shall run the `lint`, `format`, `types` and (from `mvp`) `security` steps on `{changed}`, with a `[tool.bandit]` whose `exclude_dirs` globs keep `.venv`, `scripts`, `spikes` and the tests directory out; shall add none of the runtime dependencies of R3 and R5; shall not write `ci.yml` when `.github/workflows/` already held a workflow (`own_ci`), printing instead the two steps to add to it, nor anything under `infra/` when that directory existed (`own_infra`); on the first adoption shall write no `[tool.pytest.ini_options]` when the project configures pytest (its own files, `[tool.pytest]`, `tox.ini`, `setup.cfg`: the order of ADR-0029) or has test files in its root, and otherwise only `testpaths` (the tests directory, then every other directory where `test_*.py` or `*_test.py` files were found), never `addopts`; shall refuse with exit code 2, before any write and listing them, a package directory, a layer directory, a `<package>/app/entrypoint.py` (with `--llm`) or a `<package>/pipeline.py` (kind `data` without a model) that the configuration names and the disk does not have; and shall report the pytest configuration it left alone, that no tests directory existed (it creates one for its two files), tests found outside the tests directory, and `requirements*.txt` files, which it does not copy, when `pyproject.toml` declares no dependencies. Without `--adopt` none of this applies. Adopting or not, for an existing `.claude/settings.json` or `.pre-commit-config.yaml` that it leaves untouched (R8) and that does not call the guard, `rumbo init` shall print the exact text to add (the `hooks` object of the template; the two local hooks with `default_install_hook_types` and `default_stages`).
- R11 (event): When `rumbo update` runs, the system shall replace the files the framework owns with their current version (`RUMBO.md`, the three scripts under `scripts/`, the `0000-template.md` of ADRs, specs and postmortems, `spikes/README.md`, `.claude/commands/`), create the ones that are missing together with any missing `.claude/` file and the files the rigor brings (`nightly.yml`, `dependabot.yml`), list the other harness files that differ from the current template without changing them (the architecture test under the directory `[tool.rumbo].tests` names; an existing `.claude/settings.json` is never rewritten), and leave every other file as it is; in `pyproject.toml` it shall only append the `[tool.rumbo.checks]` table or the steps of the current rigor the table lacks (never replacing or removing a step), add the keys `kind`, `layout`, `types`, `python`, `src` and, for an adopted project, `own_ci` and `own_infra` that are missing, and set `[tool.rumbo].version` to the version of the CLI wherever the key is in the table, reporting a spelling it cannot rewrite; it shall list, and rewrite neither, each check step whose command differs from the template of the level and each Makefile alias the template has and the project lacks; it shall print the `uv add --dev` line for the development tools of the level that the project does not list, and end by telling the human to commit before an agent goes on. It shall refuse with exit code 2, writing nothing, a `[tool.rumbo]` that no configuration accepts (one line, also with `--diff`) and, unless `--allow-downgrade` is given, a harness whose `[tool.rumbo].version` is newer than the CLI (release numbers compared, trailing zeros ignored; both versions named). For a project adopted before `own_ci` and `own_infra` existed it shall decide them from the names of the files until it writes them (ADR-0029: a workflow RUMBO does not write, an `infra/` without `infra/Dockerfile`). `guard_wiring`, which `rumbo doctor` prints, shall report as a problem a `.claude/settings.json` that is not valid JSON or lacks a `PreToolUse`, a `PostToolUse` or a `Stop` hook that runs `scripts/rumbo_guard.py`, and a `.pre-commit-config.yaml` that lacks a hook running it for `pre-commit` or one for `commit-msg`; and as a warning a hook whose matcher misses a tool the guard judges at that event (`EDIT_TOOLS` and `SHELL_TOOLS` before a tool, `SHELL_TOOLS`, which holds `PowerShell`, after it) and a `permissions.allow` entry that starts with `Bash(make rumbo` or `Bash(rumbo decision`.
- R12 (optional): Where `rumbo update` is given `--diff`, the system shall write nothing and print, for each harness file that differs from the current template, a unified diff headed by what `update` would do with it (`[update replaces]`, `[merge by hand]`, or `[missing; copy by hand if wanted]`), leaving out the documents the human edits, `pyproject.toml`, `.gitignore` and the `rev:` lines of `.pre-commit-config.yaml`; with nothing to show it shall print `Everything matches the current templates.`
- R13 (event): When `rumbo promote` names a rigor above the current one, the system shall build the configuration of the new level before it writes anything, rewrite only the `rigor` key of `[tool.rumbo]`, run the update of R11 for the new level (with its lists of what differs, its line about committing and its refusals; there is no `--allow-downgrade` here) and run `uv add --dev` with the tools of the level the project does not list yet (with `--no-install` it prints that line instead); when that update fails it shall put `pyproject.toml` back byte for byte, and when the failure is a refusal (a `ValueError`) exit with code 2 and name the rigor that still holds; it shall remove or replace nothing (steps, files, `AGENTS.md`, the Makefile), and shall refuse an equal or lower rigor with exit code 1 and `pyproject.toml` unchanged.
- R14 (optional): Where `rumbo init` is given `--python` (3.11, 3.12 or 3.13), the system shall store it as `[tool.rumbo].python` and render it in `requires-python`, the `target-version` of ruff, the CI matrix of a library or cli (that version and the newer supported ones), the Dockerfile and `.python-version`, and shall refuse it with exit code 2 when the `[project].requires-python` the directory already has does not allow it; without the flag, adopting or not, it shall use the lowest supported Python that `requires-python` allows (refusing with exit code 2 when it allows none), else the one `.python-version` pins (the nearest supported one, and it says so, when the pin is outside the list), else 3.11; it shall report, and rewrite neither file, a `requires-python` that allows older Pythons than the supported ones or that it cannot read (which then decides nothing), and a `.python-version` below the result or outside `requires-python`; where it is given `--types mypy` (default `pyright`), it shall store `[tool.rumbo].types`, list `mypy` instead of `pyright` among the development tools, make `uv run mypy` the `types` step and render `[tool.mypy]` instead of `[tool.pyright]`, with the innermost layer strict; any other value of either is refused with exit code 2 and nothing is written.
- R15 (unwanted): If an agent marker is set in the environment (`[tool.rumbo].agent_env`, else the default markers of the guard) or the command does not run at a real terminal (`is_console` on standard input and output; on Windows the null device is not one), then `rumbo init` shall not run `git config rumbo.human true`: it shall leave the setting as it is and print that command among its next steps while the clone does not declare it. Only for a human at a terminal, at the top of a git repository and after installing the git hooks, does `rumbo init` run the command itself; outside a repository, or in a sub-directory of one, it shall install no git hook and say so (in a sub-directory: that they belong to the repository root), and at the top of one it shall run `pre-commit autoupdate` only when it wrote `.pre-commit-config.yaml` in this run.

## Acceptance criteria
<!-- pytest tests / Hypothesis properties that verify them (path::test). A test covers a requirement
     by mentioning its full id, e.g. `F-000N.R1`, in its docstring; `rumbo trace` builds the table. -->
In `tests/test_scaffold.py`, `tests/test_cli.py` and `tests/test_render.py`; each test carries
its requirement id in a comment. `uv run rumbo trace` prints which tests cover each requirement.
`tests/test_fitness.py::test_cli_has_no_runtime_dependencies` holds R2 for the whole package.

End to end: `scripts/e2e.sh` mounts a project per flag set of the CI matrix (kinds, layouts,
rigor, `--python 3.12`, `--types mypy`) and runs `rumbo update` on it; on the prototype flag set
it runs `rumbo promote mvp` (and expects exit code 1 from a second one); on `--no-llm --rigor
mvp` it adopts a small pre-existing project.

## Data contracts and ownership
<!-- What two sessions (or two agents) must agree on BEFORE writing code. Omitting explicit data
     structures is what breaks parallel work (docs/method.md, section 3.1). -->
- Types / schemas: `[tool.rumbo]` in `pyproject.toml`, the stored state of a project: `version: str` (the harness version), `name: str`, `package: str`, `kind: "service" | "library" | "cli" | "data"` (absent means `service`), `layout: "hexagonal" | "layered" | "flat"` (absent means the default of the kind), `layers: list[str]` (only with `layered`), `llm: bool`, `provider: str` (`"none"` without a model), `sdk_package`, `sdk_module`, `sdk_env_key: str`, `rigor: "prototype" | "mvp" | "production"` (absent means `mvp`), `python: "3.11" | "3.12" | "3.13"` (absent means `3.11`), `types: "pyright" | "mypy"` (absent means `pyright`), `src: "src" | "."` (absent means `src`), `adopted: bool` and `tests: str` (written only by adoption; absent means `false` and `tests`; `tests` is one top-level folder name), `own_ci: bool` and `own_infra: bool` (written by adoption, or by `update` for a project adopted before them; absent means decided from the names of the files, R11); `[tool.rumbo.checks]` is an ordered table of step name to command. `Project` (what is read back) carries the stored fields except `own_ci` and `own_infra`; `Config` (what is rendered) adds `case`, `own_ci` and `own_infra: bool | None` (`None` means not decided yet) and `testpaths: tuple[str, ...] | None` (`None` means the tests directory, `()` means no pytest table; not stored); `plan_files(config_for(Project.load(root), root), root)` plans the same set of files as the `Config` that mounted it. `Report` lists `created`, `skipped`, `unchanged`, `merged`, `updated`, `differs`, `commands` (command, exit code), `suggested`, `notes`, `warnings` and `drift`. `Detected` holds `name`, `package`, `kind`, `layout`, `tests_dir` and `src`.
- Signatures: `Config(name, package, llm, provider="", rigor="mvp", case="", sdk_package="", sdk_module="", sdk_env_key="", kind="service", layout="", layers=(), adopted=False, tests_dir="tests", python="3.11", types="pyright", src="src", own_ci=None, own_infra=None, testpaths=None)` raises `ValueError`; `plan_files(cfg, root=None) -> dict[str, str | Path]` (target path to rendered text, or to a file copied as it is; with `root`, an adopted plan reads `own_ci` and `own_infra`); `scaffold(cfg, dest, force=False) -> Report` raises `ValueError` before it writes; `install(cfg, dest, report, human=None) -> None`; `human_present(dest, environ=None, isatty=None) -> bool`; `is_console(stream) -> bool`; `git_prefix(root) -> str | None` (`""` at the top of a work tree, `sub/dir/` below it, `None` outside one); `detect_project(root, package=None) -> Detected` raises `ValueError` on an ambiguous package; `find_package(root, package) -> tuple[str, str] | None` (`src` and the name on disk); `resolve_python(root, flag) -> tuple[str, list[str]]` (the version, what to report) raises `ValueError`; `config_for(project, dest) -> Config` raises `ValueError`; `update(project, dest, allow_downgrade=False) -> Report` raises `NewerHarness` (a `ValueError`); `update_diff(project, dest) -> str`; `guard_wiring(root) -> tuple[list[str], list[str]]` (problems, warnings); `write_text(target, text) -> None`; `set_rigor(text, rigor) -> str` raises `ValueError`; `dev_dependencies(cfg)`, `runtime_dependencies(cfg)`, `check_steps(cfg) -> list[str]`; `Project.load(root) -> Project` raises `FileNotFoundError` or `ValueError`; `render(text, ctx) -> str` raises `TemplateError` (a `KeyError`).
- Shared invariants: exit codes are 0 done, 2 refused before anything is written (an invalid configuration, what R8, R9, R10 and R14 refuse, and for `update` and `promote` no RUMBO project, a `[tool.rumbo]` no configuration accepts or a harness newer than the CLI) and for a `promote` whose update fails (R13), 1 when `promote` is asked for an equal or lower rigor or when an install command of `init` or `promote` failed; nothing the human wrote is overwritten without a copy, and no copy is overwritten; a fact about an adopted project (`src`, `tests`, `own_ci`, `own_infra`) is decided once and stored; a template tag never reaches a generated file, and a section that is dropped is not validated; `pyproject.toml` and `.gitignore` are merged, never replaced; `update` only adds to `[tool.rumbo]` and `[tool.rumbo.checks]` and writes each late key once; the three scripts under `scripts/` are copies of `src/rumbo/sensors/` and are never edited in a project; the generated project never imports `rumbo`; the development tools and the check steps of a level come from one place each (`dev_dependencies`, the rendered `[tool.rumbo.checks]`), shared by `init`, `update` and `promote`.
- Files owned by this spec (one writer): `src/rumbo/scaffold.py`, `src/rumbo/render.py`, `src/rumbo/project.py`, the `init`, `update` and `promote` subcommands of `src/rumbo/cli.py`, `src/rumbo/templates/` (except the hook entries owned by F-0001), `tests/test_scaffold.py`, `tests/test_render.py`, the `init`, `update` and `promote` tests of `tests/test_cli.py`.
- Interfaces touched that other specs depend on: the guard's `agent_env_names` decides R15, and its `EDIT_TOOLS` and `SHELL_TOOLS` the matchers of R11 (F-0001); `[tool.rumbo.checks]`, `{base}` and `{changed}` are read by the runner (F-0002); `[tool.rumbo].tests` and the copied sensor (F-0003); `Project` is read by `gate` and `trace`, and `config_for`, `plan_files`, `guard_wiring`, `git_prefix` and `release_key` by `doctor` (F-0005); `write_text` is used by `new`, `eval add` and `tour --out`.

## NFR
`rumbo init --no-install` < 2 s (PRD; about 0.3 s on a laptop, measured by hand on 2026-11-21;
no test asserts the number) · 0 runtime dependencies (R2) · 0 network calls with
`--no-install` and in `update`; the installing path runs `uv add` and `pre-commit`, which do
use the network · Linux, macOS and Windows, Python 3.11 to 3.13 (CI matrix) · generated
`AGENTS.md` < 100 lines · cost 0 USD.

## Out of scope
Monorepos and uv workspaces (in a sub-directory of a repository no git hook is installed: the
human calls the guard from the `.pre-commit-config.yaml` of the root); a package directory other
than `src/` or the root, and a project of single modules; lowering the rigor (a hand edit of
`[tool.rumbo].rigor`); removing a step, a tool or a file a level brought, and rewriting a step
or a Makefile alias that differs (R11 only lists them); a baseline file of accepted findings
(ADR-0013); `ty` as a type checker (ADR-0015); a new A0 question for layout, Python or type
checker (flags only).
Limits ADR-0029 states: `[tool.rumbo].tests` names one top-level directory, so tests found
elsewhere are collected by pytest but not watched by the sensor, `rumbo trace` and G4; adoption
checks that a module exists, not what it does (the example smoke dataset runs against the
project's own entry); `update` never rewrites `.claude/settings.json`, so an older matcher stays
a warning of `rumbo doctor`; a project adopted before `own_ci` existed whose own workflow was
already named `ci.yml` is taken for RUMBO's (`update` lists it as different, changes nothing).
What the copied scripts do is F-0001 (guard), F-0002 (runner, `{changed}`) and F-0003 (sensor).
The gates, what `rumbo doctor` prints and exits with, and `rumbo decision` are F-0005; cli
`test_new_and_decision_write_lf_and_validate_what_they_are_given` (it names F-0005.R3) holds
that `rumbo decision` refuses an empty title and a line break in the title, `--why` or `--who`,
and that `rumbo new` numbers after four-digit prefixes only and stops at 9999.
Not stated as requirements because no test verifies them: the answer `no` to the confirmation
question of an interactive `rumbo init` in a directory that is not empty (that it is asked is
asserted by `test_init_asks_the_console_not_isatty`); the real `uv add` and `pre-commit install`
of the installing path (the tests replace `uv`); that every generated Python file passes ruff,
ruff format and the type checker (that is the e2e matrix, not pytest).

## Questions raised while drafting (for the human, before signing)
- `__main__.py` is generated for every kind and layout, a library and a flat package included
  (no entry in `CONDITIONS`; `test_each_kind_generates_exactly_its_column` asserts it). ADR-0010
  gives a library `__init__` only and says a flat layout has "`src/<pkg>/__init__.py` only". R3
  states what the code does.
- `rumbo init` asks for standard input and standard output to be terminals (`at_a_terminal`);
  ADR-0021 says "standard input is a terminal". The code is the stricter one; R15 states it.
- An LLM or data project has the `evals` step at `prototype` too; the prototype list of
  ADR-0011 does not name it. R6 states what the template renders.
- A layered project whose `layers` key is missing does not load, so `rumbo update` cannot write
  that key back (`test_update_writes_layers_for_a_layered_project` shows it); R11 leaves
  `layers` out of the late keys. ADR-0010 says the loader "never fails on their absence".
- A second `rumbo init --adopt` on a project that configures pytest outside `pyproject.toml`, or
  has test files in its root, appends `[tool.pytest.ini_options]` with `testpaths`: pytest is
  looked at on the first adoption only (`_adoption`) and the merge then adds the table the
  template renders. ADR-0029 says such a project keeps its configuration. Reproduced by hand on
  2026-11-21; no test. R10 says "on the first adoption".
- The interactive package question refuses `domain`, `app` and `api` for every new project
  (`valid_package` with its default, asked before the kind); ADR-0029 refuses them only where
  the kind and layout write that sub-package, which is what `--yes` does (R1).
- ADR-0029 asks for `<package>/pipeline.py` "with `--kind data`"; the code asks for it only when
  the data project calls no model (`missing_modules`). R10 states the code.
