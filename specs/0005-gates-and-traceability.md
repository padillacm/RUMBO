# F-0005: Gates and traceability
Story: As the human who signs each phase of a project built with a coding agent I want every
gate to tell me what was verified, what failed and what could not be measured, and to show me
which test stands behind each requirement, so that I sign on evidence and the tool never signs
for me.

Scope: `rumbo gate G1…G5`, `rumbo trace`, `rumbo doctor`, `rumbo metrics` and `rumbo decision`
(`src/rumbo/gates.py`, `src/rumbo/trace.py`, `src/rumbo/metrics.py`, the reading side of
`src/rumbo/project.py`, and their subcommands in `src/rumbo/cli.py`).
Decisions: ADR-0009, ADR-0010, ADR-0017, ADR-0018, ADR-0020, ADR-0032; `docs/method.md`, sections 2 and 6.
This spec is retroactive: it states what the code does on 2026-11-21.

## Requirements (EARS)
<!-- Ubiquitous: The system shall… · Event: When…, the system shall… · State: While…, the system shall…
     Unwanted: If…, then the system shall… · Optional: Where…, the system shall… -->
- R1 (ubiquitous): `rumbo gate Gk` shall run the automatic checks of the gate and report each one in one of three states, passed (✅), failed (❌) or unmeasured (⚠️: it could not be measured, it was skipped, or it is a recommendation at the project's rigor), printing the detail of a check only when it did not pass.
- R2 (ubiquitous): The gate report shall be red (header 🛑, the number of failed checks, exit code 1) when at least one check failed and green (header ✅, exit code 0) when none failed, saying in the green case how many checks could not be measured or are recommendations; when the project state cannot be loaded from `pyproject.toml` (missing, not UTF-8, not TOML, or without a valid `[tool.rumbo]`) the command shall print one `Error:` line on standard error and exit 2 without a report.
- R3 (ubiquitous): The tool shall never sign a gate: every report shall print the gate's human checklist as unticked items under a heading that says the human signs, say `GATE NOT SIGNED yet` when no check failed, and end with the `rumbo decision "Gk signed"` command; `rumbo decision` shall append a dated entry (title, the reason when given, who decided, `human` by default) to `docs/decisions.md` with LF line endings, and shall exit 2, writing nothing, when that file does not exist, when the title is empty or when the title, `--why` or `--who` contains a line break.
- R4 (optional): Where the project's rigor is below the level a check is required from, the gate shall report a miss of that check as unmeasured instead of failed: below `mvp` the PRD, the eval plan and the G5 operation checks (dependency updates, the Python versions of a package, the runbook and the datasets of a `data` project); below `production` the data contracts of a spec and the fitness function of an ADR; and it shall ask for at least 20 real eval cases at `prototype` and 50 at `mvp`, a real case being a line of `evals/datasets/*.jsonl` that is a JSON object with an `input` key and whose `tags`, when a list, do not contain `example`.
- R5 (ubiquitous): The gate shall ask a project only for what its `llm`, `kind` and `layout` can have: eval cases and the eval plan in G2 for an LLM product or a `data` project; in G3 an ADR whose title names both "workflow" and "agent" and the row `threat model: OWASP LLM/Agentic checklist filled`, and in G5 the budget and telemetry wired into the entry point, for an LLM product; in G3 two import-linter contracts for a layout with layers and the architecture test for a `flat` one; in G5 a changelog with an Unreleased section, a release workflow with Trusted Publishing and no PyPI token secret, and CI on at least two Python versions for `library` and `cli`, a runbook, SLOs and a Dockerfile for `service`, a runbook and datasets for `data`, whose Dockerfile is a recommendation; the CI checks shall read every `*.yml` and `*.yaml` directly under `.github/workflows/` (ADR-0032): `CI runs rumbo check` (G3) passes when one workflow contains `scripts/rumbo_check.py` and its `on:` key names `push`, `pull_request`, `pull_request_target` or `merge_group`; the Python check counts the entries of the `python` or `python-version` list of a `matrix:` and takes the largest count of any workflow; `SBOM generated in CI` (G5, `production`) passes when one workflow mentions `sbom`; and where `[tool.rumbo].python` is the newest supported Python the Python check is `CI runs on Python X, the newest supported (one version is enough)` and passes when one workflow could be read.
- R6 (ubiquitous): The human checklist of a gate shall list only the items that apply to the project's rigor, `llm`, `kind` and `layout`, under the same conditions as the automatic checks, so that the human is not asked to sign what the checks do not expect.
- R7 (unwanted): If a document a gate reads still carries the template mark, then the gate shall report it as not complete (failed where the document is required at the project's rigor, unmeasured where it is recommended), and likewise a brief, PRD, eval plan, threat model, C4 document, runbook or SLO document that is empty (`<file> is empty`) and any document that is not UTF-8 (detail `<file>: not UTF-8 (save it as UTF-8)`, never a traceback); it shall count a section of the threat model, or the diagrams of the C4 document (two Mermaid blocks at least), only when the mark is gone and at least one of their lines is not a line of the template shipped with the CLI; and it shall count as an EARS requirement only a line of the `Requirements` section that is outside code fences and HTML comments, is not a line of the spec template (the CLI's or the project's `specs/0000-template.md`) and, code spans removed, says `shall` (or `deberá`) without the ellipsis character of the template's placeholders.
- R8 (event): When `rumbo gate G4` runs, it shall name the lane in the report heading, `fix` when there is at least one commit that is not a merge since the merge base of `HEAD` with the base branch and every such subject has a Conventional Commit type other than `feat` with no `!` before the colon, `normal` otherwise, and shall fail the check `small diff (≤300 lines, lockfiles excluded)` when the lines added plus removed since the merge base exceed 300, counting under the project directory only (the project may be a sub-directory of the repository) the working tree of the files git tracks plus every line of the untracked text files git does not ignore, and leaving out lockfiles at any depth; without a merge base (no repository, or `HEAD` on the base branch itself) the lane shall be `normal` and the diff size shall be reported as unmeasured.
- R9 (state): While the lane is `fix`, G4 shall add three checks on the same diff: `fix lane: regression test added`, a file under the project's tests directory gained lines since the merge base; `fix lane: diff ≤ 150 lines`, lockfiles excluded; and `fix lane: no new runtime dependency`, `[project].dependencies` of the project's own `pyproject.toml` in the working tree names no distribution, compared by normalised name, that the same file at the merge base did not have.
- R10 (unwanted): If the run was requested and the runner exits 3, or the runner or the sensor could not be started, then G4 shall fail that check with a detail saying that it is the environment and that the human repairs it; a runner or a sensor that exits 0 passes and one that exits with another code fails with the tail of its output, at most 20 lines: the end of its standard error, then the last 15 lines of its standard output, where its verdict is; the runner is `scripts/rumbo_check.py`, or `make check` when that script does not exist; the sensor is run as `scripts/check_tests_not_weakened.py --strict --base <sha>` with the merge base G4 found, also when `HEAD` is that base, and without `--base` when there is none; with `--no-run` neither is started and G4 reports one unmeasured result, `skipped (--no-run)`.
- R11 (ubiquitous): `rumbo trace` shall read as a requirement each line `- Rk (pattern): text` or `- Rk: text` of the first `Requirements` section of every `specs/NNNN-*.md` except the `0000-` template, outside code fences and HTML comments, accepting a `*` or `+` bullet, a bold id and one level of nested parentheses in the pattern; give it the id `F-NNNN.Rk`; ignore nested items such as `R1.1`; and print a table with, for each requirement, the `file:line` places in the `.py` files of the project's tests directory and in `evals/datasets/*.jsonl` that mention the full id as a whole token (`F-0001.R10` does not cover `F-0001.R1`), found in one pass over those files, or `**missing**`, followed by the count of requirements referenced; a bullet of that section that starts with an id and cannot be parsed, and a spec that is not UTF-8, shall not be dropped: they are listed after the table, with their place, under a line that says they `could not be parsed`.
- R12 (unwanted): If `rumbo trace --strict` finds a requirement that nothing mentions, a line that could not be parsed, or no requirement at all, then it shall exit 1, and 0 otherwise; without `--strict` it shall exit 0; gate G4 shall report requirements that nothing mentions and lines that could not be parsed, in the check `every spec requirement is referenced by a test or eval case`, as unmeasured below `production` and as failed in `production`, and shall add no such check when `specs/` has neither.
- R13 (ubiquitous): The system shall read the tests directory from `[tool.rumbo].tests` (`tests` when the key is absent), normalised to a relative POSIX path (`./tests/` and backslashes are accepted), for the architecture test G3 looks for, for `rumbo trace`, for the coverage check of G4 and for the regression-test rule of the fix lane, and the source root from `[tool.rumbo].src` (`src` when absent, `.` for a package at the project root) for the spikes-import scan of G1.
- R14 (event): When `rumbo doctor` runs, it shall print one ❌ line per problem and exit 1 when a file of the harness plan for this project is missing, when `AGENTS.md` has more than 100 lines, when `uv.lock` is missing, when `.claude/settings.json` is not valid JSON or lacks a `PreToolUse`, `PostToolUse` or `Stop` hook that runs `scripts/rumbo_guard.py` (`pre-tool`, `post-tool`, `stop`), or when `.pre-commit-config.yaml` has no hook that runs it for `pre-commit` and for `commit-msg`, and otherwise exit 0 with one line naming the package, kind, layout, llm, provider and rigor; it shall print as warnings, which do not change the exit code, a guard hook whose matcher misses a tool the guard judges (the edit tools, `Bash`, `PowerShell`), a `permissions.allow` entry that begins with `Bash(make rumbo` or `Bash(rumbo decision`, the `@your-handle` placeholder in `.github/CODEOWNERS`, the security-contact placeholder in `SECURITY.md`, a git work tree in which `rumbo.human` is not `true`, and a harness version in `[tool.rumbo]` that differs from the CLI's (`run 'rumbo update'`) or is newer than it (`upgrade rumbo`).
- R15 (ubiquitous): `rumbo metrics` shall compute offline, and print as text or with `--json` as JSON, the specs (total, closed), the sessions per closed spec and their median, the gates signed, the deploys and incidents logged inside the `--days` window, the postmortems, the commits of the window by Conventional Commit type, the requirements with and without a test, the real eval cases and a summary of the latest eval report; the window shall start at 00:00 of the day `--days` days ago for commits and decisions alike, and `--days` shall be a whole number from 0 to 36500, anything else being a usage error of the parser (exit 2, `--days must be between 0 and 36500`); it shall read decision headings written by hand (hyphen, en dash or em dash, CRLF) and shall count as nothing, without failing, git that is not installed, a directory that is not a repository, a decision heading with an impossible date, a dataset line that is not a JSON object with an `input`, an eval report that is not JSON, and a decisions log, dataset line or eval report that is not UTF-8; without a `pyproject.toml` it shall exit 2.

## Data contracts and ownership
<!-- What two sessions (or two agents) must agree on BEFORE writing code. Omitting explicit data
     structures is what breaks parallel work (docs/method.md, section 3.1). -->
- Types / schemas: `Result(description: str, ok: bool | None, detail: str = "")`, where `ok` is `True` passed, `False` failed, `None` unmeasured; `Item(text, min_rigor="prototype", llm_only=False, max_rigor="production", arch_only=False, kinds=())`, where an item with `max_rigor="mvp"` is listed only below `mvp`; `Gate(code, phase, manual: tuple[Item, ...], checks: tuple[Check, ...])` with `Check = Callable[[Project, bool], list[Result]]`; `Workflows(texts: dict[str, str], unreadable: list[str])`, the workflows by relative path and a message per workflow that is not UTF-8; `Requirement(spec_id, rid, text, covered_by: list[str], malformed: bool = False, where: str = "")` with `full_id == f"{spec_id}.{rid}"`, where `where` is `specs/NNNN-x.md:line` and a `malformed` entry is a line that could not be parsed (`text` is the line) or a spec that is not UTF-8 (`rid` is `?`, `where` the file); `Decision(date, title, why, who)`; `Metrics` (`days`, `specs_total`, `specs_complete`, `specs_closed`, `sessions_per_spec`, `gates_signed`, `deploys`, `incidents`, `postmortems`, `commits_by_type`, `commits_total`, `test_change_approvals`, `requirements_total`, `requirements_uncovered`, `eval_cases`, `latest_eval`), whose `as_dict()` adds `median_sessions_per_spec`. A decision entry in `docs/decisions.md` is `## YYYY-MM-DD — title`, `- Decision: title`, `- Why: reason` (optional), `- Decided by: who`.
- Signatures: `evaluate(code, project, run=True) -> tuple[Gate, list[Result]]`; `report(gate, results, project) -> tuple[str, bool]` (the text and "no check failed"); `merge_base(root) -> tuple[str | None, str]` (sha and base name, or `None` and the reason); `diff_size(root) -> tuple[int | None, str]`; `lane(root, base) -> "fix" | "normal"`; `trace(root, tests=None) -> list[Requirement]`; `requirements(spec, name="") -> list[Requirement]`; `uncovered(reqs)` (nothing mentions it, or malformed) and `unparsed(reqs) -> list[Requirement]`; `collect(root, days=30, today=None) -> Metrics`, raising `ValueError` when `days` is not in 0..36500; `parse_decisions(text) -> list[Decision]`; `eval_cases(root) -> int`; `dataset_cases(root) -> tuple[int, list[str]]` (real cases, datasets with a line that is not UTF-8); `Project.load(root) -> Project`, raising `FileNotFoundError` or `ValueError`; `Project.read(rel) -> str | None` and `read_utf8(path, name="") -> str`, raising `NotUTF8` (a `ValueError`); `prose(text) -> str` (comments and fenced blocks blanked, line numbers kept); `normalise_tests_dir(value) -> str`; `tests_dir(root) -> str`. Commands: `rumbo gate {G1..G5} [--dir D] [--no-run]`; `rumbo trace [--dir D] [--strict]`; `rumbo doctor [--dir D]`; `rumbo metrics [--dir D] [--days N] [--json]`; `rumbo decision TITLE [--why W] [--who WHO] [--dir D]`.
- Shared invariants: exit codes are 0 (no failed check; nothing missing), 1 (a failed check, a doctor problem, `trace --strict` with a gap) and 2 (no project, no decisions log, a refused decision, a usage error); the gate code is accepted in either case. The limits are 300 lines for a diff and 150 in the fix lane; the lockfiles left out of the count, at any depth, are `uv.lock`, `poetry.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`; the base branches tried, in order, are `origin/main`, `origin/master`, `origin/HEAD`, `main`, `master`, the list of the runner and of the sensor; the fix-lane types are `fix`, `test`, `refactor`, `chore`, `docs`, `ci`, `perf`, `style`, `build`; the diff is the working tree against the merge base, plus the untracked files git does not ignore. The minimum of real eval cases is 20, 50 and 100 for `prototype`, `mvp` and `production`. The runner's exit codes are 0 green, 1 red, 3 environment (ADR-0006, ADR-0018). A numbered document is `NNNN-*.md` and never `0000-*`; a document is "under the template mark" when the mark string appears anywhere in its text, or when the file is missing. A line is the template's when, without whitespace and with runs of dashes folded, it equals a line of the template; a `{{variable}}` of the template stands for any text. A file is not UTF-8 when it does not decode as UTF-8 or holds a NUL; a BOM is dropped and CRLF is read as LF. A CI check that passes carries `in <workflow>` as its detail; one that fails names the workflows that are not UTF-8. A requirement id is `F-NNNN.Rk`, `NNNN` being the number of the spec file; a mention counts wherever it is in a file (docstring, comment, string, case id), once per line. `rumbo metrics` reads decision titles `F-NNNN closed` (with `k sessions` in the reason), `Gk signed`, `deploy…` and `incident…`; closed specs and signed gates count whatever their date, deploys and incidents only inside the window; a spec that is not UTF-8 is not complete and counts as one requirement without a test. The keys of `[tool.rumbo]` read here are `package`, `rigor`, `kind`, `layout`, `layers`, `llm`, `provider`, `tests`, `src`, `python` and `version`.
- Files owned by this spec (one writer): `src/rumbo/gates.py`, `src/rumbo/trace.py`, `src/rumbo/metrics.py`, `tests/test_gates.py`, `tests/test_trace_metrics.py`, and `cmd_gate`, `cmd_trace`, `cmd_doctor`, `cmd_metrics`, `cmd_decision` with their parsers in `src/rumbo/cli.py`.
- Interfaces touched that other specs depend on: `Project`, `is_template`, `section`, `prose`, `read_utf8`, `tests_dir`, `SUPPORTED_PYTHONS` and `numbered_documents` in `src/rumbo/project.py`, shared with the scaffold (F-0004) and the tour (F-0006); the template mark, which the guard reads with its own copy of the constant (F-0001); the templates shipped under `src/rumbo/templates/`, which the gates compare documents with (F-0004); the exit codes of the runner (F-0002) and of the sensor under `--strict --base` (F-0003), and their `DEFAULT_BASES`; `plan_files`, `config_for`, `guard_wiring`, `git_prefix` and `release_key` of the scaffold, which give `rumbo doctor` the harness files, the guard wiring and the version order (F-0004); `[tool.rumbo].tests`, also read by the sensor (F-0003).

## Out of scope
A check that every feature of the PRD has a spec: the human decided against it (2026-11-09);
the features already built got their specs instead. The catalogue of checks of each gate beyond the rules above (`GATES`, `_g1`…`_g5` in
`src/rumbo/gates.py` are the list). Who runs `rumbo decision`: the command does not check its
caller, and no gate reads the log to know whether it was signed. What the sensor and the runner
decide (F-0003, F-0002). Whether a test that mentions a requirement verifies it: `rumbo trace`
finds mentions, the reviewer judges them. A fix that changes behaviour a spec describes without
updating the spec (ADR-0009).

Limits of the workflow checks, which read text and not YAML (ADR-0032): a commented-out runner
step passes; a `push` limited to tags, one branch or some paths counts as verifying a change; a
runner called only through a reusable workflow (`on: workflow_call`) does not pass; the Python count
reads an inline or a block list under `matrix:`, not `include:` entries nor a `fromJSON`
expression. Other limits: a C4 whose only edit is the system name still equals the template
(that line carries a variable); an empty spec or ADR without the mark is complete.

Read in the code and not stated above, because no test verifies it: the data contracts of a spec
and the fitness function of an ADR failing in `production`; the 100-case minimum in `production`;
the threat model and the C4 document as recommendations below `mvp`; at most three `file:line`
places per file in the trace table and the `(duplicate id!)` flag; the fix lane's dependency
check reported as unmeasured when `pyproject.toml` cannot be read; `rumbo doctor` exiting 2
without a project; `test_change_approvals` in the metrics; the `nightly.yml` check of G4 in
`production`. The pre-approval warning is tested on `guard_wiring`, not through `rumbo doctor`.

## Questions open while interrogating the spec
- `rumbo trace` and the coverage check of G4 read the requirements of a spec that still carries
  the template mark, while G2 reports that spec as not complete. In `production` a draft with
  an untested requirement turns G4 red. Should a draft's requirements count?
- The mark is looked for anywhere in a document, not only on its first line, although the gate's
  message says "on its first line": a signed document that quotes the mark reads as a template.
- A red report still ends with the line that tells how to record the signature.
- With the run requested, an unmeasured diff size (no merge base) leaves G4 green: ADR-0018
  makes only the runner and the sensor fail when they cannot be measured.
- A missing sensor script, or a sensor that exits 2 because no base was found for it, fails its
  check with the sensor's own output and without the hand-off to the human that ADR-0018
  describes; only an interpreter that cannot be started gets that text.
- A requirement id inside a fixture string of a test counts as a mention of the real
  requirement; RUMBO's own tests now build such ids at run time.
